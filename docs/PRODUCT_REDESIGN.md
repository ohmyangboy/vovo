# vovo 产品重设计与最佳实践调研

> 状态：规划稿，尚未实施界面与业务重构。
> 调研日期：2026-10-09。
> 范围：当前 Tauri + React 桌面应用，以本地语音生成、声音选择/克隆、音频与字幕导出为核心。
> 最重要的设计约束：面向普通用户，常用功能与全局配置分开，而不是美化一个极客工具面板。

## 1. 核心结论

**产品应该从「配置模型并运行脚本」变成「选择一个声音，把文稿变成可用的配音与字幕」。**

建议做一个轻量、本地优先的语音创作工具，不做完整 DAW、视频剪辑器或模型实验平台。

六个关键决策：

1. **一个工作台、一个生成流程**：预设音色和克隆声音使用同一份文稿、同一套播放器、字幕与导出。
2. **功能与配置分离**：生成工作台、声音库、生成记录是用户功能；模型资源、运行环境、保存位置放进设置。
3. **区分模型选择与模型管理**：任务中的模型切换保留轻量入口；下载安装、版本与依赖不占据工作台。
4. **声音是资产，不是一次性表单**：克隆完成后命名保存为「我的声音」，下次直接选择。
5. **先试听再交付**：音频生成后在应用内播放、核对字幕，导出无需重新推理。
6. **能力真实且可解释**：不显示不起作用的语速/情绪滑块；不把毫秒时间格式说成字词级精确对齐；不把参考音频克隆说成训练专属模型。

首版优先保留当前已经接入的 Kokoro 和 Qwen3-TTS MLX，不为了重设计同时引入大量新模型或云服务。

## 2. 当前功能与真实能力

### 2.1 已具备的基础

| 领域 | 当前实现 | 重设计处理 |
| --- | --- | --- |
| 桌面外壳 | Tauri 2 + React + TypeScript，macOS / Windows / Linux | 保留，不改为 SwiftUI 或 Web 服务 |
| 文稿 | TXT / MD / DOCX 导入、拖拽、文本输入弹窗 | 保留输入渠道，改成主界面直接编辑 |
| 普通配音 | Kokoro v1.0、v1.1-zh | 保留适配器，统一资源状态和生成结果 |
| 音色 | v1.0 清单 54 个，v1.1-zh 清单 103 个 | 搜索、筛选、收藏、友好名称 |
| 语速 | Kokoro 0.80–1.30 | 留在任务面板，不移到全局设置 |
| 克隆 | Qwen3-TTS 0.6B Base，经 MLX-Audio；当前仅 Apple Silicon macOS | 从独立生成卡片改为声音创建流程 |
| 克隆参考 | 本地音频、3–20 秒片段、准确逐字稿 | 保留，增加选段试听和可复用保存 |
| 普通输出 | MP3（24 kHz / 96 kbps）+ SRT | 扩展为共同的音频/字幕产物服务 |
| 克隆输出 | WAV / MP3（160 kbps）/ SRT / TXT | 与普通配音统一格式与行为 |
| 字幕 | 根据逐句实际音频长度累计时间 | 作为句级字幕基础，不宣传词级对齐 |
| 执行约束 | Rust 层共享任务互斥，克隆可取消 | 保留互斥优势，统一任务状态与取消 |
| 隐私 | 克隆推理显式离线，不上传参考录音 | 保留；普通引擎离线就绪还需补齐资源检查 |

音色数量已通过本地清单代码核对；不是对每个音色的音质或语言效果背书。

### 2.2 主要问题与证据

| 问题 | 用户影响 | 代码依据 |
| --- | --- | --- |
| 普通配音与克隆是两套完整表单 | 两次输入文稿、两套输出目录、两种结果体验 | `src/App.tsx`、`src/components/CloneCard.tsx` |
| 运行环境未就绪时连文稿输入也禁用 | 用户必须先处理技术配置才能开始创作 | `src/App.tsx`、`src/components/DocumentCard.tsx` |
| 音色是很长的原生下拉框，中文多为编号 | 用户不懂 `zf_001`，也难以比较声音 | `src/components/SettingsCard.tsx`、`engine.py` 的音色清单 |
| 模型下载、删除与语速、声音混在一起 | 高频创作和低频维护互相干扰 | `src/components/SettingsCard.tsx` |
| 克隆卡片暴露引擎、模型、起点数字、逐字稿、目标文案 | 更像技术调试面板，而非用户产品 | `src/components/CloneCard.tsx` |
| 克隆录音不能保存为声音资产 | 同一个人反复导入录音、填写参考文字 | `src/components/CloneCard.tsx` |
| 文稿只展示前三段预览，编辑藏在弹窗里 | 无法在主要工作区域持续修改文案 | `DocumentCard.tsx`、`TextInputSheet.tsx` |
| 默认模型固定英文，切换模型后声音直接重置为首项 | 与中文界面和用户选择不一致 | `src/App.tsx` 的初始状态、`onModelChange` |
| 普通结果没有应用内完整播放器，结果只保留最后路径 | 试听、查找旧结果、重新导出不方便 | `GenerateCard.tsx`、`src/App.tsx` |
| 普通配音直接写入相同名称的 MP3/SRT | 再生成可能覆盖旧文件 | `engine.py` 的 `cmd_generate` |
| 模型「已安装」检查偏粗，音色资源仍按需下载 | 下载了权重不一定代表断网可生成 | `model_installed`、`cmd_download`、`build_pipeline` |
| 音色语言清单比实际管线更宽 | 声音可选不代表相应语言已正确适配 | 普通分支固定 `lang_code='a'`，克隆固定 `lang_code='chinese'` |
| 字幕只有写文件，没有阅读性设置、同步预览与校对 | 生成字幕不等于字幕已经能直接交付 | `write_srt`、`GenerateCard.tsx` |
| 多个前端 busy 布尔值和无任务 ID 的事件 | 进度、错误、历史结果的归属不清晰 | `src/App.tsx`、`clone.rs`、`lib.rs` |

另外进行了不加载模型的文本处理验证：

- `购买价 19.99 元。版本 1.5 已发布。` 被错误切成四段。
- `请保留【重要条款】和[产品名称]。` 被清洗成 `请保留 和 。`。
- 600 字无标点文本没有按 `max_len=260` 限制进一步切分。

这些是输入与内容正确性问题，必须随重构修复，不能仅用新 UI 掩盖。

已有 `test_clone_engine.py` 的 3 个测试通过；本次没有下载新模型、运行真实语音推理或进行音质/性能基准测试。

## 3. 官方产品调研：借鉴什么，不照搬什么

调研依据是公开官方操作指南、API 文档、模型卡和固定版本源码。没有登录付费账号逐项实测，因此以下是可核实的产品模式，不是音质排行榜，也不是供应商性能结论。

| 产品/模型 | 官方可核实实践 | 对 vovo 的启发 | 不照搬的部分 |
| --- | --- | --- | --- |
| ElevenLabs TTS / Voice Library [S1][S2] | 文稿、声音、模型和生成；声音搜索、语言/口音/用途筛选；My Voices 与试听 | 工作台以声音和文稿为中心；用可浏览声音选择器代替巨大下拉框 | 声音市场、推荐榜单、商业化分享不是首版必需 |
| ElevenLabs Studio [S3] | 生成状态、段落重生成、生成历史、播放、导出；生成与导出区分 | 明确「已生成/已修改」；保留结果版本；改格式不重生成 | 多轨音乐、SFX、视频、Agent 会扩大复杂度 |
| ElevenLabs Instant Voice Cloning [S4] | 导入/录制、命名、确认授权、保存声音，随后在 My Voices 使用 | 克隆是创建声音，不是第二个工作台 | 其 1–2 分钟建议不能作为所有本地模型的通用门槛 |
| Fish Audio [S5][S6] | 克隆声音保存为可复用 ID；预设与克隆都传入 TTS；区分一次性与持久声音 | 同一生成接口接收 `voiceId`；声音资产默认私有 | 云端持久声音 ID 不等于可在本地导出的模型权重 |
| MiniMax [S7][S8][S9] | TTS 分离模型、声音、音频配置；提供字幕及粒度；克隆后用 `voice_id` 合成 | 能力声明要结构化；字幕不是简单附带路径；云端声音需有失效状态 | 云端限额、上传、音色有效期不能藏在「本地」体验里 |
| Descript [S10][S11][S12] | 写文稿并选 speaker；模型设置独立；克隆需要声音本人的录制授权；SRT/VTT 可设每行字符和行数 | 高频创作与全局配置分离；字幕校对和导出阅读性；声音创建重视授权 | 不做完整视频编辑器，也不未经验证复刻自动重生成 |
| Qwen3-TTS [S13][S14] | Base、CustomVoice、VoiceDesign 是不同能力；Base 用参考音频与文字克隆；官方 Python 接口可复用参考 prompt | 模型能力决定界面；本地「保存声音」先保存参考资料，不假装训练新权重 | 原版 GPU 示例和时延不能直接当成本机 MLX 表现 |
| Kokoro [S15][S16][S17] | 轻量预设音色；各语言需要相应 G2P 管线；v1.1-zh 并非 v1.0 音色全集的直接升级 | 音色与模型兼容性必须显式管理；不能随意迁移声音 | 不把模型列出的全部语言直接标为本 App 已支持 |

额外发现：

- 不同产品的克隆样本要求不同：Qwen 官方描述可从 3 秒克隆，当前 App 接受 3–20 秒；Fish 建议至少 10 秒；MiniMax 克隆源要求至少 10 秒；ElevenLabs 建议约 1–2 分钟。**创建向导必须按当前适配器提供提示。**
- MiniMax 当前文档说明未在 7 天内使用的克隆声音会被删除 [S9]。如果将来接入云服务，声音列表必须能表达过期/失效，而非只存一个字符串。
- ElevenLabs 有独立 Forced Alignment 能力 [S18]。说明「生成声音」和「获取字词时间」是不同能力，不能混为一谈。
- MLX-Audio v0.5.8 Qwen3-TTS `generate` 源码说明 `speed` 尚未直接支持，Base 克隆也不是带任意风格指令的 CustomVoice [S19]。传入参数不代表参数生效。
- 官方产品文档中也存在新模型说明与旧 FAQ 不完全一致的情况。实现时以固定版本适配器、接口契约和实际测试为准，不从通用 FAQ 推导全模型能力。

## 4. 信息架构：把常用功能和配置真正分开

### 4.1 顶层导航

```text
生成工作台
声音库
生成记录
──────────
设置
```

- **生成工作台**：每天完成主要任务的地方。
- **声音库**：寻找、收藏、创建、重命名和管理声音。
- **生成记录**：试听历史版本、再次导出、使用旧文稿和参数。
- **设置**：低频的资源、环境、存储、界面偏好与高级配置。

不增加首页仪表盘、模型商城或独立「克隆配音」页。

### 4.2 三类信息，不一刀切

| 类型 | 放置位置 | 例子 |
| --- | --- | --- |
| 高频创作功能 | 工作台常驻 | 文稿、声音、语速（支持时）、试听、生成 |
| 当前任务选项 | 工作台轻量选择器/导出弹窗 | 模型覆盖选择、目标语言、导出格式、是否附带字幕 |
| 全局配置与维护 | 设置 | 模型安装/删除、运行环境、默认保存目录、缓存、主题、诊断日志 |

**语速不能因为「它是一个配置项」就被移进设置；模型下载也不能因为「与生成有关」就长期占着工作台。**

模型选择与管理的具体分工：

- 设置中的「模型与资源」负责安装、完整性检查、修复和卸载。
- 工作台显示低调的 `本地生成 · 自动推荐` 摘要；点击可查看推荐理由并手动换模型。
- 模型选择器先显示用途、语言、是否就绪；型号、版本在次级详情中保留，不隐藏事实。
- 未安装时展示「需要准备资源」和按钮，不展示一个不解释原因的禁用控件。
- 准备资源从工作台触发时进入设置中的对应安装流程；完成后回到原文稿和选择，不丢上下文。

## 5. 主界面布局与视觉方向

### 5.1 工作台线框

```text
┌────────────┬───────────────────────────────────────────────────┐
│ 生成工作台  │  未命名文稿                         已自动保存     │
│ 声音库      ├─────────────────────────────┬─────────────────────┤
│ 生成记录    │  导入文稿                    │ 声音                │
│            │                             │ 中文女声 001   更换  │
│            │  直接输入或粘贴文稿……       │ 播放声音示例        │
│            │                             │                     │
│            │  大面积、可持续编辑的文稿   │ 语速    1.00×       │
│            │                             │                     │
│            │                             │ 本地生成 · 自动  ▾  │
│            ├─────────────────────────────┴─────────────────────┤
│            │  320 字 · 预计音频约 1 分钟   试听文稿    [生成]   │
│            ├───────────────────────────────────────────────────┤
│ 设置       │  生成结果：播放器 / 字幕预览             导出 ▾   │
└────────────┴───────────────────────────────────────────────────┘
```

线框中的时长仅为示意；实际显示须标明估算，不是生成耗时承诺。首次空状态不放占满屏幕的空结果面板。

### 5.2 布局规则

- 建议默认窗口约 1100 × 800；保留 720 × 620 的最小可用尺寸。
- 宽窗口使用窄导航、主编辑区、约 280–300 px 的声音/任务面板。
- 宽度不足约 980 px 时导航改为紧凑顶部入口，任务面板移到编辑区上方或抽屉，避免三列硬挤。
- 生成结果位于编辑区下方；可切换音频/字幕，不做首版多轨时间线。
- 编辑区和字幕区有明确滚动边界；生成操作保持可见，不因页面拉长而滚到屏幕外。
- 设置使用独立页面，不在每个创作区域下塞一个「高级参数」卡片。

### 5.3 视觉原则

- 中性色底色、一个强调色、清晰的字号与间距；不是大面积玻璃、渐变或满屏卡片。
- 用留白和分组组织信息，减少边框层级；保留平台字体与原生文件选择器。
- 正文约 14 px，文稿约 16–18 px，主要控件约 36–40 px 高。
- 声音用名称、类型标签、语言和播放按钮表达，不用虚构人物头像制造真实身份错觉。
- 深浅色均需验证对比度；键盘焦点可见；不能只靠颜色区分成功/失败/过期。
- 主要操作一个强调色按钮；取消、设置、导出不与「生成」争夺同等视觉权重。
- 动效短、克制；尊重 Reduce Motion；不为装饰引入 WebGL 或复杂动画库。
- 点击目标至少符合 WCAG 的尺寸/间距要求，主要操作采用更宽松尺寸 [S20][S21]。

## 6. 核心功能规划

### 6.1 文稿：先能开始，再准备模型

首版：

- 主界面直接编辑、粘贴；导入 TXT / MD / DOCX；文件拖入后仍能编辑。
- 标题可改、显示字数、自动保存草稿；刷新或重启不丢文稿。
- 没有安装引擎也能写文稿、浏览声音元数据。
- TXT/MD 解析不依赖 TTS Python 环境；DOCX 解析拆成独立能力检查，不能用 TTS 未就绪阻挡所有输入。
- 保留原文，合成清洗不修改用户文稿；对于不会读出的内容提供明确说明。
- 支持明确的「插入停顿」操作，底层转成结构化停顿，不删除所有方括号内容。
- 估算音频长度基于语言、字数、语速，显示「约」；不把音频时长当推理耗时。

文本处理必须覆盖：中英文标点、英文缩写、小数、日期、版本号、引号、URL、空行、无标点长段落和混合语言。

原文、合成文本、字幕显示文本分别存储映射；数字/发音替换后字幕通常仍显示用户原始表达。

### 6.2 模型：推荐优先，选择透明

首版实际支持范围：

| 模型 | 用途 | 用户界面描述 | 约束 |
| --- | --- | --- | --- |
| Kokoro v1.1-zh | 中文和中英混读的预设配音 | 中文配音 · 本地 | 优先验证中文及内置英文声音，不宣称所有语种可用 |
| Kokoro v1.0 | 英文预设配音 | 英文配音 · 本地 | 美音/英音应使用对应语言管线；其他语种验证后再开放 |
| Qwen3-TTS 0.6B Base / MLX | 参考录音声音克隆 | 我的声音 · 本地克隆 | 当前仅 Apple Silicon Mac；中文、英文及混读按文本自动路由 |

默认策略：

1. 优先恢复用户最近一次有效的声音与模型。
2. 没有有效选择时，根据界面语言/文稿语言提供推荐；中文首次使用不默认英文音色。
3. 选中克隆声音时，提示所需模型；不把克隆音色传给 Kokoro。
4. 手动换模型若与当前声音不兼容，先说明需要换声音并让用户确认；不静默重置到首项。
5. 只推荐真正可执行的适配器；型号下载体积、运行内存、实测速度分开描述。

模型管理在设置里展示：就绪/未安装/下载中/缺少资源/不支持/需修复、下载来源、磁盘占用、依赖与许可。

「可离线生成」必须验证权重、配置、选中音色、tokenizer/G2P 及依赖齐备；不能仅凭存在 `.pth` 或完成标记推断。

### 6.3 声音选择：可听、可找、可复用

声音选择器与声音库共享组件：

- 分组：推荐、全部预设、收藏、我的声音。
- 搜索名称、标签和 ID；首版主要过滤语言、预设/克隆、收藏。
- 每条显示名称、语言、类型、兼容状态和独立播放按钮。
- 默认隐藏技术 ID，详情中可复制。
- 已有可靠描述的音色可用「温暖」「清晰」等标签；未知音色先用「中文女声 001」，不能凭编号杜撰音色性格。
- 试听不自动选择声音；选择不自动启动推理；只允许一个播放器同时发声。
- 收藏、最近使用、用户重命名保存到本地。

两种试听必须区分：

- **声音示例**：固定短句，缓存命中后立即播放；首次生成时明确等待，不偷偷下载模型。
- **试听文稿**：用户选中的一段或开头短段，使用当前生成参数，属于一次短推理任务。

声音示例缓存键至少包含模型 revision、音色/参考资料 hash、试听文本、有效参数与引擎版本。音频 Blob URL 用完释放；长音频避免经 JSON 字节数组反复复制。

### 6.4 克隆：创建「我的声音」，不要创建第二个工作台

从声音库的「创建我的声音」或选择器中的「+ 克隆声音」进入向导：

```text
选择参考录音 → 选段并核对文字 → 生成短句试听 → 命名保存 → 回到工作台使用
```

首版每个环节：

1. **选择参考录音**：本地导入；说明仅本人/获授权声音，默认私有、不上传。
2. **选段**：展示波形或轻量音频选段器、起止范围、所选片段试听；数字微调放次级区域。
3. **核对参考文字**：只输入片段实际说过的话；明确它不是要生成的文案。当前适配器保留准确逐字稿要求。
4. **质量检查**：格式、可解码、实际长度、空音频/静音、异常样本、明显削波；提示单说话人、少噪声、稳定表达。高级说话人/噪声识别不伪装成已实现。
5. **短句试听**：用一小段测试文案验证；可重选参考片段，不先跑长文。
6. **保存**：用户命名，保存为声音资产，返回主工作台；原目标文稿保持不变。

当前适配器接受 3–20 秒，优先提示选一个完整、干净的短片段；其他供应商接入时由适配器提供不同要求。

本地保存内容：受应用管理的参考片段、逐字稿、名称、语言、创建日期、兼容模型、来源说明、授权声明和试听结果。只引用用户原始文件路径不够，原文件移动会导致声音失效。

**这是零样本参考条件的复用，不代表训练了新模型。** 固定版本 MLX 能验证的 prompt 缓存可利用，但不直接假定原版 Qwen Python 的 prompt 序列化接口同样可用。

授权应是独立确认，不埋在提示段落里；可保存授权说明或证明文件入口。用户勾选不等于身份/版权验证，不宣称其足以替代法务要求 [S4][S6][S11]。

麦克风录制、自动转写、自动降噪属于后续增强；不会为了「简单」默认新增云端上传或未经确认的模型下载。

### 6.5 生成：统一任务与清楚的反馈

生成前预检查：

- 有有效文本；模型/声音兼容；语言在已支持范围；依赖和声音资源就绪。
- 克隆声音的参考资料有效且授权声明存在。
- 有足够工作磁盘空间；后端没有冲突任务；任务参数符合适配器范围。

阶段提示：

```text
准备资源 → 载入声音 → 生成第 3 / 12 段 → 整理字幕 → 保存结果 → 完成
```

- 没有可量化总量的模型加载不显示虚假百分比。
- 下载显示字节进度，合成显示段落/句子进度，编码单独显示阶段。
- 所有推理任务可取消；首版保持一个重任务执行，不盲目并发多个模型。
- 取消后保留文稿与已完成历史，不把未完成文件标成成功。
- 编辑允许继续，但运行任务使用启动时的不可变快照；完成后提示是否对应当前文稿。
- 生成失败保留上一份成功结果，并标出新任务失败，不清空一切。
- 可理解的错误出现在任务区；完整技术详情通过「查看详情」进入诊断，不自动把 stdout 铺到主页面。

### 6.6 文件与字幕：同一组可交付成果

**生成与导出在数据层分开，但不给用户增加每次选目录的负担。**

- 生成结果先安全保存在应用管理目录，并加入历史。
- 用户点击「导出」一次选择格式/目录；记住上次位置和格式。
- 设置中可启用「完成后自动导出到默认位置」，保留高频一键交付体验。
- 重新导出 MP3/WAV/SRT 不重新推理；音频播放倍速不改变导出语速。
- 默认导出 MP3 + SRT；可另选 WAV 与 TXT；VTT 为后续增强。
- 原始音频保存为模型原生采样率 PCM/WAV；MP3 从该源编码，不把有损 MP3 改容器包装成高质量 WAV。
- 统一两种引擎的编码策略，码率作为可选导出设置；不把提高采样率/码率描述为提升模型音质。
- 文件使用同一基名与唯一版本标识；同名时追加编号/时间/短 ID，不覆盖旧产物。
- 「在文件夹中显示」「复制字幕」「再次导出」直接可用。

字幕首版：

- SRT 使用句级实际音频边界；展示「句级字幕，建议核对」，不声称已验证每个词。
- 播放时高亮当前条目；点击条目跳转音频；可校对文本并重新导出。
- 提供基础断行与最多两行的阅读性处理；具体字符阈值是产品默认，不宣称国际统一标准。
- 超长句可以在同一 cue 内断行；拆成多个有独立时间的 cue 需要真实细粒度时间，不能用平均分时伪装精确。
- 字幕修正文字符号不强制重生成音频；实质文案变化提示「只修改字幕不会改变配音」，可选择同步改文稿并重新生成。
- 时间需满足非负、开始小于结束、顺序正确、不越过最终音频，停顿默认不显示文本。
- 文稿/声音/合成语速变化后，旧结果标为历史版本或待更新；不能把旧字幕当成新配音字幕。

后续精准字幕：优先使用模型真实 alignment；不具备时接入可选本地 forced alignment，明确额外模型、磁盘与耗时。检测漏读/重复或真实词级字幕也属于此阶段。

**最终字幕时间以最终导出音频为准。** 若后处理改变语速或裁剪音频，必须一起调整/重建时间轴；MP3 编码延迟与 gapless 播放差异需实际校验。

## 7. 首次使用与日常使用

### 7.1 新用户，没有安装资源

1. 打开即能看到编辑区、示例文稿和声音选择入口。
2. 选择声音并点击生成后，仅提示当前任务需要准备哪些本地资源、下载量和来源。
3. 经确认进入设置中的准备流程；详细环境检查与日志留在那里。
4. 完成后回到原任务；用户确认继续生成，不未经提示启动长任务。

准备资源可以从设置主动开始，但不要求用户理解 Python、uv、FFmpeg 才能填写文稿。

### 7.2 日常预设配音

```text
粘贴/导入文稿 → 使用上次声音或换声音 → 可选试听 → 生成 → 校对/导出
```

已有资源后不再展示安装区、不必每次选目录、不必每次选择模型。

### 7.3 日常克隆配音

```text
写文稿 → 选择「我的声音」 → 生成 → 同一个播放器与字幕 → 导出
```

仅首次创建需要参考录音；后续使用与预设音色没有第二套表单。

## 8. 技术结构：支持产品，而不是把技术暴露给用户

继续使用 React/Tauri/Rust/Python，优先模块化重构，不重写推理栈。

### 8.1 领域对象

| 对象 | 职责 |
| --- | --- |
| `ModelDescriptor` | 资源 ID、适配器、语言、平台、音色模式、能力、revision、许可、安装状态 |
| `VoiceAsset` | 预设/克隆、名称、元数据、兼容模型、参考片段/文本、授权、试听缓存 |
| `Draft` | 标题、可编辑原文、上次有效选择、自动保存版本 |
| `GenerationSpec` | 文稿、声音资料 hash、模型/引擎版本、语言、有效参数的不可变快照 |
| `Job` | 任务 ID、种类、阶段、进度、取消与可恢复错误 |
| `ArtifactBundle` | 音频、字幕、源文稿、参数 manifest、时长、采样率、结果/字幕版本 |

模型清单和音色元数据应在 Python 环境未安装时可查询；不能再依赖 `env.ready` 才能显示模型。

### 8.2 能力驱动界面

能力至少区分：预设声音、参考克隆、指令风格、原生语速、后处理变速、语言、时间戳粒度、平台和取消。

- Kokoro 可展示经过验证的原生语速控件。
- 当前 Qwen MLX Base 通过 FFmpeg `atempo` 提供保持音高的输出变速，控件明确说明会应用到导出文件；字幕按最终音频长度同步调整。
- 播放器仍支持独立播放倍速，不改变导出文件。
- Base、CustomVoice、VoiceDesign 用不同能力描述，不能只看到 Qwen 名字就开放全部参数。
- 当前任务的参数范围来自固定适配器；不假定所有提供商都支持 pitch、emotion 或 speed。

### 8.3 统一适配器与任务服务

- 统一 `listModels / listVoices / prepare / preview / generate / cancel` 契约，保留 Kokoro、Qwen MLX 的独立环境。
- Rust 后端是任务互斥和合法性检查的权威；前端禁用只是交互优化。
- 事件携带 `jobId`、事件序号、阶段、进度单位和结果引用；旧任务不能更新新任务状态。
- 检查进程退出码并转换成明确失败，不能只依赖是否碰巧收到 `error` JSON 行。
- 取消需要处理 Python 及 FFmpeg 等子进程树；完成/失败/取消均释放锁和模型。
- 默认不永久驻留大模型；后续根据实测决定有限的预热/驻留策略，不把「即时试听」当成已有性能。

### 8.4 保存与安全

- 首版可使用 Rust 管理、带 schema version 的 JSON 索引和原子写入；不用为了几十条记录先引入复杂数据库。
- 推理输出到唯一临时目录，完整性校验后提交整个结果目录；跨磁盘导出在目的盘 staging，写完再发布。
- 一个 manifest 表达完整产物组；只有所有必需文件成功，才登记为成功结果。
- 资源下载固定 revision、校验所需文件；中断可续传；共享 Hugging Face 缓存卸载需避免误删其他应用资源。
- 播放和文件访问限定在授权导入/应用产物范围；评估替代当前任意路径 `read_audio` 与关闭 CSP 的做法。
- 本地录音不入日志、不进仓库；日志诊断尽量隐藏用户内容与路径，提交诊断前可预览。
- 将来云服务必须单独启用，明确上传哪些数据、费用与供应商，密钥放系统凭证存储；本次首版不接入。

### 8.5 前端组件边界

建议从当前卡片式结构拆成：

```text
AppShell
├── WorkspacePage
│   ├── ScriptEditor
│   ├── GenerationOptions
│   └── GenerationResult（AudioPlayer / CaptionPreview / Export）
├── VoiceLibraryPage（共享 VoicePicker / CloneWizard）
├── HistoryPage
└── SettingsPage（ModelManager / RuntimeStatus / Storage / Diagnostics）
```

`App.tsx` 不再负责全部表单、播放器、安装日志和结果状态；前端不再另造一套克隆 API 和结果模型。

已有工作区包含未提交的克隆实现；落地时在现状上渐进迁移，不覆盖、丢弃或回退这些修改。

## 9. 优先级与实施顺序

### P0：完成真正可用的新版

1. **信息架构与工作台**：独立设置，直接编辑，统一任务/结果；补自动保存与首次使用状态。
2. **模型与声音联动**：静态目录、能力声明、兼容性、就绪检查；搜索/试听/收藏；技术维护移出工作台。
3. **克隆资产化**：创建向导、片段试听、准确参考文字、授权、私有保存；从主工作台使用克隆声音。
4. **统一交付**：可取消任务、结果播放器、句级字幕预览/文本校对、MP3/WAV/SRT/TXT、唯一文件名、历史与重新导出。
5. **内容正确性**：数字/括号/长文本切分、语言路由、离线资源检查、产物完整性和错误恢复。

建议按「先契约和状态 → 工作台/设置 → 声音库与克隆 → 文件字幕与端到端验收」推进。新壳可先展示，但不能将纯视觉版本算作产品重设计完成。

### P1：提高效率与质量

- 改动段落的局部重生成、段落缓存与版本对比。
- 更细粒度字幕对齐、VTT、字幕时间编辑与阅读性预设。
- 发音字典；中英混读、数字和品牌名称的发音辅助。
- 本地可选转写、麦克风录制、选段质量辅助。
- 按硬件测试再扩展 Qwen 其他语言/平台或其他本地引擎。
- 大文件分段落盘与文件流播放，完善内存与启动性能。

### 本轮不做

- 账号/团队/云同步、声音市场、模型排行榜。
- 多角色对话、多轨混音、视频编辑、背景音乐生成。
- 为追求模型数量同时接入多个云 API。
- 不经实测宣称实时、零延迟、绝对相似或自动精准字幕。

## 10. 验收标准

### 普通用户体验

- [ ] 工作台不出现 Python、uv、FFmpeg、venv 路径、安装日志和模型删除按钮。
- [ ] 未安装模型仍能编辑/保存文稿、浏览声音；准备资源后恢复原任务。
- [ ] 常用声音、语速、试听、生成无需跳进设置；模型安装与默认目录无需挤进工作台。
- [ ] 首屏主操作清楚；720 × 620 与大窗口都可用，不横向溢出。
- [ ] 试用目标：邀请 5 位非技术用户，在资源就绪后至少 4 位无需讲解完成首次配音与导出；这是验证目标，不是已完成结果。

### 模型和声音

- [ ] 更换不兼容模型会说明后果；不会静默换声音；失败时保持有效原选择。
- [ ] 不支持克隆的设备能用普通配音，并能理解克隆为何不可用。
- [ ] 克隆声音重启后可复用；移动原始录音不影响已保存的参考片段。
- [ ] 未确认授权、参考文件损坏、静音、超时长都在长推理前有明确提示。
- [ ] 没有不生效的速度/情绪控件；语言能力与实际路由一致。
- [ ] 冷启动断网也能用标为「离线就绪」的已准备声音生成，未准备资源不会隐式联网下载。

### 生成、文件和字幕

- [ ] 预设与克隆使用同一个生成、播放器、字幕、导出流程。
- [ ] 下载/加载/生成/编码进度不混用，旧任务事件不能污染新任务。
- [ ] 取消在有界等待内停止进程树，不提交半成品，锁释放后可再生成。
- [ ] 再生成不覆盖同名文件；失败不丢上一份成功结果；重启后能找回历史。
- [ ] 修改格式和重新导出不再次推理；字幕校对结果可保存。
- [ ] 原文小数、版本号、普通方括号内容与长段落不被误切或删掉。
- [ ] 字幕与最终音频时长一致；多条、单条、跨分钟/小时、尾部停顿均通过时间轴测试。
- [ ] 字幕文字更改、文稿更改、变速后的音频有明确版本关系，不能导出不匹配的一组文件。
- [ ] 播放、焦点、弹窗退出、错误提示、键盘操作、Reduce Motion 与深色对比度可用。

推荐测试语料：纯中文、纯英文、中英混读、数字/金额/日期、缩写、括号、短句、长句、无标点文本；克隆还需测试片段末尾、空录音、削波、路径不存在以及相同声音重复使用。

性能评估须区分冷加载、热推理、缓存试听、导出耗时与峰值内存；在具体设备上记录，不用供应商 API 首包时延承诺本地整段速度。

## 11. 待确认项与默认建议

1. **平台**：默认继续跨平台桌面应用；当前本地克隆仅 Apple Silicon。跨平台克隆需要另立适配器验证任务。
2. **隐私和成本**：默认首版纯本地，不加入登录、API key 或云服务。后续需要云服务再单独设计。
3. **使用场景**：默认中文/中英短视频旁白、课程和日常文案；先做好单声音任务，不先做广播剧与多角色长篇制作。

这些默认不阻碍先完成工作台、声音库、设置分离的设计。
